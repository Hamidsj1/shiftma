# مشخصات الگوریتم شیفت

## A) FAITHFUL (APK اصلی؛ کلاس ex) — [PROVEN FROM CODE] + [PROVEN BY BYTECODE EMULATION]
```
serial(Y,M,D) = -1  اگر Y<1397 ؛ وگرنه D + Σ daysInMonth(y,m)  (y=1397..Y ، m=1..(y==Y?M-1:12))
daysInMonth: m≤6→31 ؛ 7..11→30 ؛ 12→ (y%33 ∈ {1,5,9,13,17,22,26,30}) ? 30 : 29
idx = (serial(target)-serial(base)) rem n ؛ اگر idx<0: idx+=n ؛ result = pattern[idx]
```
پیاده‌سازی: tools/faithful.py

## B) IMPROVED (این برنامه)
```
diff = JDN(target) - JDN(base)      // JDN با الگوریتم Borkowski، اعتبارسنجی‌شده
idx  = floorMod(diff, n)            // معادل rem + اصلاح منفی، بدون تقسیم بر صفر (n≥1 اجباری)
result = pattern[idx]
```
### تفاوت‌ها (هر کدام خطایی از APK اصلی را برطرف می‌کند)
| # | APK اصلی | IMPROVED |
|---|---|---|
| 1 | تاریخ قبل از ۱۳۹۷/۱/۱ → شمارندهٔ ثابت ۱- (همه یک شیفت) | محاسبهٔ واقعی برای سال‌های ۱..۳۰۰۰ |
| 2 | تاریخ نامعتبر (۳۰ اسفند سال عادی) بی‌صدا با روز بعد یکی می‌شد | رد می‌شود (isValid / IllegalArgumentException) |
| 3 | دو قانون کبیسه (۳۳ ساله برای شیفت، Borkowski برای «امروز») | یک موتور واحد |
| 4 | الگوی خالی → ArithmeticException؛ کد خارج از ۱..۶ بی‌صدا حذف | خطای صریح |
| 5 | محاسبهٔ بازه: تاریخ پایان باید اکیداً بعد از شروع باشد | (در نسخهٔ فعلی ابزار بازه‌ای ندارد؛ گزارش ماهانه جایگزین است) |

### تضمین سازگاری
برای هر تاریخ معتبر از ۱۳۹۷/۱/۱ تا ۱۶۳۳/۱۲/۲۹ با مبدأ معتبر، نتیجه با APK یکسان است (قانون کبیسه در این بازه
یکسان است). فقط در ۱۶۳۴، ۱۶۳۵، ۱۶۶۷ و ۱۶۶۸ قانون کبیسه فرق دارد (محاسبه‌ای، نه اجرای bytecode).
