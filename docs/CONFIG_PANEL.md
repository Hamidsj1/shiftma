# پنل تنظیمات بخش‌ها (نمایان / پنهان / پولی)

هر چند ساعت، برنامه فایل `config.json` محل کار کاربر را از گیت‌هاب می‌گیرد (مثل پنل اعلان‌ها و تبلیغ) و بر اساس آن
بخش‌های صفحهٔ اول را نشان می‌دهد، پنهان می‌کند، یا پشت قفل پولی می‌گذارد. کاربری که فایل کاشی‌های آن محل را وارد نکرده باشد،
هیچ درخواستی نمی‌فرستد و همه‌چیز برایش نمایان و رایگان است.

## فایل‌ها
| فایل | کار |
|---|---|
| `core/RemoteConfig.kt` | خواندن `config.json` (منطق خالص، تست‌شده) |
| `core/PaidAccess.kt` | کد باز شدن بخش پولی، آفلاین و مخصوص هر گوشی |
| `system/ConfigLoader.kt` | دریافت دوره‌ای فایل (WorkManager، هر ۳ ساعت) و نگه‌داشتن آخرین تنظیم سالم |
| `ui/PaidGate.kt` | صفحهٔ قفل بخش پولی |
| `tools/shiftma_paid_code.py` | ساخت کد برای ادمین |
| `test/.../RemoteConfigTest.kt` | تست‌ها (هم‌خوانی کد کاتلین و پایتون هم هست) |

## ساختار گیت‌هاب
کنار `ad.json` و `notice.json` هر محل:
```
shiftma-ads/sungun/config.json
```
```json
{
  "enabled": true,
  "payLink": "https://example.ir/pay",
  "sections": { "sport": "hide", "reading": "paid" }
}
```
مقدارها: `show` (پیش‌فرض)، `hide`، `paid`. شناسهٔ بخش‌ها همان `HomeSection.id` است
(`payslips`، `notes`، `files`، `income`، `prayer`، `english`، `pay`، `sport`، `reading`، `dhikr`).
بخش‌های `settings`، `about` و `shift` هرگز پنهان یا پولی نمی‌شوند.
## به‌روزرسانی آدرس سایت‌ها
وقتی آدرس یک سامانه عوض شد، بدون وارد کردن فایل جدید می‌شود از همین `config.json` اصلاحش کرد:
```json
"sites": [ { "key": "nicicocom", "url": "https://new.example.ir", "title": "عنوان تازه", "subtitle": "توضیح" } ]
```
- فقط `key` و `url` لازم است؛ `title` و `subtitle` اختیاری‌اند. `key` همان شناسهٔ سایت در فایل کاشی‌هاست (پیش‌فرض: دامنه بدون نقطه).
- فقط سایتِ موجود در گوشی عوض می‌شود؛ سایت تازه اضافه نمی‌شود، و نام کاربری/رمز ذخیره‌شده دست نمی‌خورد.
- اگر کاربر خودش سایت را ویرایش کرده باشد (دکمهٔ «ویرایش» در تنظیمات)، تغییر ادمین اعمال نمی‌شود: ویرایش دستی کاربر اولویت دارد.
- قواعد: https، بدون `@` و IP، حداکثر ۳۰ مورد (`core/SiteUpdates.kt`، تست: `SiteUpdatesTest`). پنل ادمین همین قواعد را دارد.

برای برگرداندن همه‌چیز به حالت عادی: `"enabled": false` یا پاک کردن بخش از `sections`.

نشانی فایل را در **فایل کاشی‌های** همان محل با کلید `configFeed` بگذارید (باید https و روی گیت‌هاب باشد):
```json
"configFeed": "https://raw.githubusercontent.com/Hamidsj1/shiftma-ads/main/sungun/config.json"
```
فایل خراب یا غیرقابل‌خواندن، آخرین تنظیم سالم را عوض نمی‌کند.

## باز کردن بخش پولی برای یک کاربر
1. کاربر از لینک پرداخت می‌کند و شناسهٔ ۸ حرفی صفحهٔ قفل را برای ادمین می‌فرستد.
2. `python3 tools/shiftma_paid_code.py AB12CD34 reading`
3. کد ۸ رقمی را برایش بفرستید؛ کاربر وارد می‌کند و بخش برای همیشه (روی همین نصب) باز می‌ماند.

## قبل از انتشار
- `PaidAccess.SECRET` و `SECRET` در اسکریپت را عوض کنید (هر دو یکی باشند) و اسکریپت را عمومی نکنید.
  بعد از عوض کردن، مقدارهای `codeMatchesPythonTool` در `RemoteConfigTest` را دوباره از اسکریپت بگیرید.
- تغییر config تا حدود ۳ ساعت دیرتر به گوشی‌ها می‌رسد.
- این قفل جلوی کاربر عادی را می‌گیرد، نه کسی که APK را باز کند.
- قانون بازار برای فروش بخش‌های داخل برنامه با لینک پرداخت بیرونی را قبل از انتشار بررسی کنید.

## هم‌گام‌سازی خودکار آدرس کاشی‌ها (۱.۰.۱۴)
فایل کاشی‌ها (`.shiftma`) فقط با «ورود فایل» توسط کاربر وارد گوشی می‌شود؛ انتشار آن روی گیت‌هاب به‌تنهایی چیزی را عوض نمی‌کند. تغییر آدرس بدون ورود فایل فقط از کانال `sites` در `config.json` است. پنل ادمین حالا هنگام ساخت `config.json`، سامانه‌های دارای شناسه (key) برگهٔ «کاشی‌ها»ی همان محل را خودکار در `sites` می‌گذارد (ورودی دستی اولویت دارد). شرایط: کلید یکسان با کاشی گوشی، آدرس https، و کاشی در گوشی با دست ویرایش نشده باشد؛ رسیدن تغییر تا ~۳ ساعت (و با هر باز شدن برنامه یک بررسی فوری).
